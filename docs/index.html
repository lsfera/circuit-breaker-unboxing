Per-API egress circuit breaker events

Services call third parties through a shared egress path. When one of those third parties degrades, everything downstream needs to be told — per API, as discrete events, reliably enough to act on.

Protecting the request path and telling the rest of the system about it are different problems with different correct answers, and most of the obvious designs conflate them. This repository separates them, runs both halves against real infrastructure, and writes down what that surfaced.

The shape of it

Enforce
EnvoyOutlier detection on every replica of the egress proxy. One address for callers, no replica names, no admin ports.
Decide
AggregatorReads each replica's view, takes a quorum, and runs one breaker per API. A lease, fencing tokens and checkpoints make the leader replaceable mid-incident.
Publish
CloudEventsOne gapless, non-repeating sequence per API, over webhook, SSE and AMQP — with a durable outbox so a subscriber that was down gets what it missed.
React
Daemon fleetFive competing consumers that throttle themselves from the stream: stop pulling on OPEN, one broker-elected prober on HALF_OPEN, ramp back on CLOSED.

The whole of it, in one picture

Two planes and a loop. The data plane enforces on the request path, per replica, immediately. The control plane decides once, off that path, and publishes the verdict. The fleet reacts by changing how much work it sends back into the data plane — which is what closes the circle.

Three things in that picture are the whole design. Enforcement is local, so it survives the control plane being down. The verdict is one, so five consumers and a status page cannot disagree about whether an API is up. And the arrow from the control plane back to the fleet carries a contract — a gapless per-API sequence — so a subscriber can tell a missed event from a quiet one.

Running it

One command brings up Envoy, three proxy replicas, two aggregators, RabbitMQ, Redis, Prometheus, Grafana and the daemon fleet, then drives a full incident end to end and prints the delivery contract as read from outside the publishing process.

pnpm install
pnpm start          # the stack, on the simulated fleet
pnpm demo:envoy     # drive a real incident through real Envoy

There is no build step: TypeScript runs natively through Node's type stripping. tsc --noEmit is still load-bearing, because the guarantees this system relies on are type-level. See Operating it for the metrics, dashboards and alerts that come up with it.
